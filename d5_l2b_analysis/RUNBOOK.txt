5. Outputs and interpretation

  measured_transport.csv
    REQUEST/CYCLE/ADAPTER/SESSION actual app-framed bytes/frames, both endpoints'
    inclusive socket times, payload/framing bytes and FULL savings. STOP/BYE bytes
    are assigned once to the adapter's last request. Request model bytes include
    that assignment; do not add them again. A real cycle group0 means cycle1,
    group1 means cycle2 (zero-based authenticated cycle_index).
  measured_ud_compute.csv
    cpu_deltas wall compute, service, pacing, serialization/deserialization/hash,
    operations, rows, FULL savings and adapter breakdown. TCP wait is separate.
  bandwidth_sensitivity.csv / ud_sensitivity.csv / combined_sensitivity.csv
    Actual baselines and MODELED target delays; sum-request E2E and means, delta,
    speedup, strict benefit, quality/token/output confounds, scenario assumptions,
    TTFT bounds (no phase point estimate), feasibility caveats and runtime support.
  break_even_summary.csv
    SESSION/CYCLE/ADAPTER roots, win direction, minimum LoRA saving, extreme upper
    bound, missing-data reasons and NO_OBSERVED_BREAK_EVEN baseline-only status.
  gpu_validation_candidates.csv
    Only supported reference-scenario SESSION cases with MODELED speedup>1.
    EXACT first, single-axis before combined, milder slowdown first. Empty means
    no supported modeled candidate OR missing measurements: inspect metadata.
    Compare all assumed scenarios before proposing a manual future GPU check.
  hypothetical_ud_assumptions.csv
    Optional, explicitly ASSUMED_MODELED, never used as measured data.
  input_mapping.csv / analysis_metadata.json / analysis_inventory.json
    Explicit path mapping, original verification bindings/identities, provenance,
    analyzer hashes and output hashes. analysis_inventory is the completion marker
    and explicitly NOT a LIGHT receipt, numerical audit, signature or CPU approval.
  assumptions_and_limitations.md
    Detailed modeling/overlap/phase/fidelity limits; read before conclusions.

Root equations (all changes MODELED):
  D0 = Cache_E2E - FULL_E2E
  S  = FULL_LoRA_wall - Cache_LoRA_wall
  A  = 0.008 * (FULL_effective_bytes - Cache_effective_bytes)
  D(B,f) = D0 - exposure*A/B - exposure*S*(1/f-1)
  unlimited => network increment0; equality is NOT speedup>1.
  At fixed B, R = D0 - exposure*A/B:
    f_root = exposure*S / (exposure*S + R), valid only in (0,1].
  At fixed f, R = D0 - exposure*S*(1/f-1):
    B_root = exposure*A/R, valid only when positive.
  Negative/zero savings may yield no crossing or a reversed win region. Roots are
  never labeled observed. Same B/f is applied to ALL modes; ES/proofs/semantics/
  CPU serialization/hash are not scaled. The serial reference reflects blocking
  sparse RPC; partial exposure and duplex-max are uncalibrated stress assumptions.
  No assumed overlap is a confidence interval or a guaranteed hardware bound.

6. What WSL alone can conclude from the attached rounded means

At unlimited/factor1 all six cache comparisons are slower. Required baseline
LoRA compute saving per request under the serial reference:
                         UD-50          UD-25
  2Wiki EXACT            >9175.503ms     >3058.501ms
  2Wiki APPROX           >10098.383ms    >3366.128ms
  Qasper EXACT           >9472.365ms     >3157.455ms
  Qasper APPROX          >9711.994ms     >3237.331ms
  MultiNews EXACT        >7869.768ms     >2623.256ms
  MultiNews APPROX       >9430.660ms     >3143.553ms

For UD-50, both Qasper/2Wiki modes and MultiNews APPROX require a saving larger
than their entire FULL E2E. They cannot cross in the frozen serial additive UD-
only model even under the extreme assumption that FULL is all LoRA and cache
LoRA is zero. MultiNews EXACT UD-50 is only theoretically possible under a very
large compute saving; no actual saving is supplied. UD-25 feasibility, bandwidth
roots and combined roots require real measured CPU costs/bytes on SERAPH.
Do not claim the hypothetical fraction table establishes a real crossing.
