# R5-I5R-3B small unoptimized baseline

LOCAL IMPLEMENTATION ONLY. Real 3A artifacts/datasets are on SERAPH, not available
locally; real selection, the 200/43/61/0 natural counts and 19 authorized pairs /
17 contexts with common prefix >=1000 remain NOT_REPRODUCED_LOCALLY. No GPU
measurements, HITs, quality improvements or strict numerical PASS are claimed.
The research stage completes only after manual GPU execution and independent audit.
No I5R-4 optimization or later dataset evaluation is implemented.

## Workloads, safeguards and budgets

All files are additive; scripts delegate actual execution to unchanged script119,
I5 GPU runtime, TinyBERT (one cluster, w=3), three separate CPU UD processes and
actual localhost TCP. Each condition reloads one base model and starts new
sessions/empty cache. Thirty users/three distinct rank-8 synthetic adapters remain
validated. No production inference, admission, LRU eviction, 64-entry policy,
512 MiB per-adapter capacity, sharing, generation or numerical threshold changes.

Preparation verifies explicit 3A plan/audit/independent-verification directories,
all SHA inventories and archived source Git blobs. It recomputes 3A results from
real sealed datasets and the verified offline tokenizer, rather than trusting
summary counts. It checks the independent receipt's binding and re-prepares
actual prompt text/IDs. Adapter evidence uses its R5 manifest. Qasper B2 token IDs
must exactly equal the 3A audit IDs. The 32-token original QA reservation is retained
for prompt preparation; target generation is then limited to eight real tokens.
No additional context is silently inserted because the output budget shrinks.

`i5r3b_protocol.json` records recomputed three-dataset summaries and Qasper pair
counts >=512 / >=1000, distinct context counts and supplied 19/17 agreement or
DISAGREEMENT (not forced equality). Different question strings, original IDs,
distinct final prompts, exact identical original contexts and original authorized
routing are all mandatory for B2. Selection is deterministic, with distinct
positive and negative contexts between groups. No rerouting occurs.

| Profile | Per-group ABC workload | A0 scored requests | Independent groups |
|---|---|---|---|
| B1 | Source64 + Target256 | 1 | 1 |
| B2_SMOKE | Source512 + Target1 + Target2 + negative | 3 | 1 |
| B2_THREE_ADAPTER | Same B2 sequence per adapter | 3 per block | 3 distinct contexts |

B1 preserves established token-sliced source mechanism, one source token and up
to eight target tokens, same original user/adapter. It requires an exact 256-token
final prompt; no synthetic extension. An optional `--historical-r1-audit PATH`
verifies a sealed real R1 exported audit and archived source; it records compatible
64:256 observations separately. It does not assert identical sample IDs/routing,
rerun an old source audit, pool old results or replace the new B1 measurement.

B2 source is a **CONTROLLED_STANDALONE_SOURCE**, generated by slicing the first
512 authoritative token IDs of Target1, also equal to Target2[:512]. Decoded text
is semantic input only. Source completes normal real generation/admission before
target arrival. Both positive targets are distinct original dataset questions;
the different-context negative keeps its original authorized route and cannot
match that source prefix. This is a constructed shared-context reuse setup,
**not natural physical reuse**. All tasks have zero-based positions/all-ones masks
through the existing request contracts. Full target+8 <=2048. No fake grants,
entry selection, hidden prefix recomputation, oracle tensors or fallback paths.

Raw QKV storage uses 3 x 32 x 2560 x 2 = 491520 bytes/token. Source64 requires
31457280 bytes (30 MiB); Source512 requires 251658240 bytes (240 MiB). These are
stored Q/K/V bytes, not consumed K/V bytes; cached Q is never consumed.
Actual sources/targets and their admission outcomes remain runtime observations.
Two 512-token sources could fit (480 MiB), but churn is NOT_IMPLEMENTED: the optional
microprobe is deferred, no capacity/policy manipulation is used. Zero evictions
are valid. Long completed MISS targets can be denied admission; this is reported.

B1 uses 8 GiB evidence per condition; B2 uses 16 GiB per condition, the existing
I5 maximum. Source and both positive targets have predetermined STRICT_AUDIT;
negative uses scalable evidence with all TCP/metadata audit. A0 retains corresponding
target evidence levels. Resource estimates come from existing `resources()`;
GPU estimate must remain <22 GiB, with actual allocated free-memory preflight.
One manually allocated RTX3090, 4 CPU cores, 64 GiB Slurm RAM, three hours maximum;
ABC and A0 each have a 4800-second parent bound, no retries. Worst-case disk
reservation per B2 group is 6 x 16 GiB +1 GiB (97 GiB); B1 49 GiB. Inspection prints
actual plan resource estimates, request/forward counts are in sealed resources.
No long-context capacity failure is silently treated as a HIT.

## A0 and timing interpretation

Each group has a separate target-only A0 experiment with the same scored requests,
order and policies and no source. To preserve the existing I5 runner and strict
independent auditor, A0 also executes auxiliary B/C conditions (six total condition
runs per group). **Only A0 FULL_RECOMPUTE is the economic reference**; auxiliary
B/C are excluded from that denominator. This conservative extra execution cost
is explicit; no unverified fourth runtime path is added.

A/B/C warm comparisons use positive target means; negatives are reported separately.
Source-inclusive sequence span includes source, admission and between-request work;
full sequence amortization divides by all scored targets (B2: three including
negative, B1: one). Positive-only source-through-last-positive span is also saved.
A0-vs-C economic comparison includes the source only in C. The matched A-vs-C
comparison includes equivalent constructed-source cost in both. Process startup,
warmup and lifecycle are separate scopes, never summed with nested model timers.
Instrumented measurements include evidence work; admission instrumentation is
not identified as pure GPU copy time. First-token, model/prefill/decode timings,
actual CPU LoRA time and rows, directional/prefill/decode/control TCP bytes,
projection rows omitted, grants, reused tokens, admission and real evictions come
from strictly audited runtime records. I5 per-request cache/quality/fidelity reports
remain accessible; no reconstruction of imaginary performance measurements.

Scientific verdicts independently report functional physical reuse, cache
integrity, token/text equality, native Qasper F1, frozen numerical tolerance,
warm-target benefit and source-inclusive economic benefit. Independent evidence
audit PASS does not imply functional/numerical PASS. Missing HITs retain reasons
and never trigger an automatic altered retry. The first run must be reviewed
before any three-adapter job. Eight-token F1 is functional/descriptive, not final
benchmark quality. All numerical failures remain visible. Strict PEFT parity and
correctness-qualified speedup remain unestablished. Kernel mechanism remains
UNRESOLVED; the earlier attention shape sensitivity finding is not a fix.
