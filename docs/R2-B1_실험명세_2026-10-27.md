# R2-B1 실험 명세서 v1.0 — OPT Exact Prefix KV Cache Reuse: 구현·정확성·실제 Forward Skip 검증

- 작성일: 2026-10-27 (KST)
- 프로젝트: `GP_semcache` / SERAPH / 현재 작업 브랜치 기준 `exp/raw-semcache-r2` (실제 실행 시 Git 상태 재기록)
- 상위 로드맵: R1(완료) → R2-A(완료·Freeze) → **R2-B1(본 문서)** → R2-B2(정량 Latency) → R2-B3(Break-even) → R2-B4(Source/E2E)
- 연구 분류: **EXACT_PREFIX_BASELINE**, 단일 모델·단일 Adapter·동일 Prefix 내 논리적 정합성 실험. `semantic_reuse_safety_claimed=false`; 교차 사용자 의미 기반 재사용을 증명하지 않는다.
- 변경 원칙: R1/R2-A/A5 런타임·Executor·CacheGen·기존 성능 결과 및 Slurm 설정 보존; R2-B1 독립 경로 추가
- 환경: `facebook/opt-125m` FP32/32-token GPU Smoke → `facebook/opt-2.7b` FP16/128·256-token 소규모 Correctness Pilot, RTX 3090 24GB, 모델 다운로드 기본 금지

## 0. 연구 질문 / B1 성공 정의

**질문:** 입력 앞부분이 완전히 동일할 때, 원래 `OPTForCausalLM`의 Causal Attention **K/V Cache**를 사용하여 Prefix 전체의 Layer Forward를 대상(Target) 요청에서 생략하고 새로운 Suffix만 계산할 수 있는가? 이 실행이 정확한 Token/Position/Adapter 조건에서 Full과 어느 정도 일치하는가?

R2-B1은 구현·정합성·물리 계산 생략 확인 단계다. **성능 우위의 통계적 검정은 R2-B2/B3**에서 수행한다. Smoke에서 유리한 Latency가 나와도 R2-B1의 완료 기준은 `speedup>1`이 아니다.

### 앞선 결과와 차이

| 항목 | R1 / R2-A | R2-B1 |
|---|---|---|
| 저장/재사용 객체 | Layer별 Q/QKV projection output(실제로 QKV 3종), Contiguous Assemble | 표준 Causal Attention의 `past_key_values`, Layer별 **K/V** |
| 신규 Target의 Layer 입력 | Full `L`개 Token (QKV 일부 행만 Fresh) | **Suffix `S=L−P`개 Token만** 각 Decoder Layer 입력 |
| Token별 Attention/FFN | Full Sequence에서 계속 계산 | **과거 Prefix 토큰은 Target에서 계산하지 않음**; Suffix의 Attention/FFN만 수행 |
| 원리적 전제 | Semantic Cluster/W3, 보수적 검증 | **정확히 동일한 처음 P개 Token IDs와 모델/Adapter/Position**, causal self-attention |
| 안전성 주장 | `safe_reuse_claimed=false`, FP16 strict fail | **동일 Prefix 전제의 로컬 캐시 Baseline**만. FP16 Strict PASS를 관측 전 주장 금지 |
| 사용 코드 | R1-82, R2-A 83/84 | 별도 85 및 R2-B1 diagnostics |

R1-B3-C2 3회 독립 실행은 128-token Full 76.09ms vs Contiguous 140.66ms; 256-token Full 77.62ms vs Contiguous 180.83ms였다. R2-A5에서는 Oracle 반복 `SourceBackingDescriptors.validate()` 한 호출의 진단용 제거가 128에서 11.33ms, 256에서 23.39ms를 감소시켰다. **이 수치는 R2-B1 새 측정값이 아니다.** R1은 `use_cache=False, output_attentions=True`; R2-B1의 `use_cache=True` 모델 경로와 직접 수치 대조 금지.

## 1. 정의와 동등 비교

하나의 정수 Token ID 시퀀스 `X=[x_0,...,x_(L−1)]`를 Prefix `A=X[:P]`, Suffix `B=X[P:]`로 나눈다. 본 단계에서는 배치 1, Padding 없는 시퀀스, `0<P<L`, 입력에 사용된 모든 special tokens/BOS가 **동일한 Prefix Token IDs에 포함**된다.

- **F — `FULL_USE_CACHE`:** `model(input_ids=X, attention_mask=ones(1,L), use_cache=True, ...)`를 한 번 실행한다. 각 Decoder Layer의 Target query length는 `L`.
- **S — `PREFIX_SOURCE_PREFILL`:** `model(input_ids=A, attention_mask=ones(1,P), use_cache=True, ...)`를 **독립 실행**하여 실제 Prefix K/V를 캡처한다. 반드시 Target 측정 전에 완료한다. Forward 출력 Cache Sequence Length는 P. Source 비용 및 메모리는 별도 보고.
- **H — `EXACT_PREFIX_WARM`:** 위 S에서 만든 동일 모델/Adapter/Token/Position/Backend Prefix K/V를 공급하고, `model(input_ids=B, past_key_values=prefix_kv, attention_mask=ones(1,L), use_cache=True, ...)`를 호출한다. **Layer의 신규 Query/FFN 입력은 S개**이고, 각 Layer는 캐시된 P개 Key/Value를 참조한다.
- **Z — `P=0` 기준 대조(선택):** 캐시 없이 전체 입력 X를 처리하며 F와 Exact. `P=0`에서는 Prefix K/V 재사용을 주장하지 않는다.

모든 조건: `model.eval()`, `torch.inference_mode()`, 동일의 Synthetic PEFT `user_a` (rank 8, alpha 8, dropout 0), OPT 모델·Tokenizer revision, FP dtype, `attn_implementation='eager'`, 동일 device, 동일 padding/mask/position 의미, `return_dict=True`. Output-attentions 설정도 동일하게 기록해 Freeze한다. 캐시가 정상적으로 작동하도록 B1에서는 `use_cache=True`가 필수.

**Logits 비교 정렬:** F의 `logits[:, P:L, :]`와 H의 `logits[:, 0:S, :]`를 비교한다(최종 Next-Token logits는 각각 `logits[:, -1, :]`). 이것은 **해당 위치에서 다음 Token을 예측하는 Logits**의 비교다. 첫 Suffix 토큰 자체를 예측하는 Logit은 Prefix 마지막 위치 `P−1`의 Logit이므로 H의 Suffix 출력 첫 행과 잘못 맞추지 않는다. 필요하면 S의 마지막 Logit과 F의 `P−1` 위치를 별도 비교한다. `logits_to_keep` 등 버전별 최적화 인자가 있는 경우 B1 Correctness에서는 모든 필요 위치의 Logits를 강제로 반환하게 설정하고 실제 Shape를 검증한다.

### Position/Mask API 및 버전 이슈

Transformers `>=4.40,<5`, PEFT `0.20.0`(repo pyproject)을 선언하지만 SERAPH의 **실제 설치 버전이 기준**이다. 버전에 따라 `past_key_values`는 legacy `(K,V)` tuple 모음 혹은 `Cache` 객체이고, OPT Forward의 `position_ids`/`cache_position` 수용 여부가 다르다. Codex는 **실제 설치 OPT forward signature를 introspection**하여 버전 호환 어댑터를 작성해야 한다. 새 라이브러리 버전의 코드를 옮겨오다가 Unsupported kwargs를 억지로 전달하지 않는다.

- H의 `attention_mask`는 신규 S만이 아니라 **전체 P+S 길이**로 구성한다(설치 버전/실제 OPT 경로에서 확인).
- H의 Suffix 위치는 절대 위치 `[P,...,L−1]`이 되도록 OPT의 Learned Positional Embedding/past length 기반 로직으로 입증한다. OPT에 RoPE가 있다고 가정하지 않는다.
- 필요 시 OPT 내부 Embed Positions 입력/출력과 Layer0 position 관련 효과를 동작 시 관찰한다. 런타임이 의미를 보장하지 않으면 `UNSUPPORTED_POSITION_HANDLING`으로 실패한다.
- Source가 중간 Substring 또는 다른 History 뒤의 토큰인 경우 **정확한 Prefix 조건에 해당하지 않으므로 재사용 금지**.

## 2. Cache 객체의 불변성 — 가장 중요한 구현 Gate

Source Prefill 결과의 Prefix Cache를 그대로 H에 넘겼을 때 Transformers의 `Cache` 구현이 K/V를 inplace append하는 경우가 있다. 측정 Repeat 2번째부터 Prefix 길이가 커지는 오류를 절대 허용하지 않는다.

구현은 다음 중 **실제 버전에 작동하는 합법적인 방식을 하나 선택하고 증거를 기록**한다.

1. Prefix Source Cache를 immutable tensor snapshot으로 보관하고, H 요청마다 새 Cache Container를 구성한다. 실제 Request 수행에 필수인 clone/copy/allocate 비용은 **Warm Target Request timer 내부**에 포함한다. 원본의 Shape/Value/Version/Device/Hash 불변 확인.
2. 지원되는 legacy tuple이 Target Forward에서 수정되지 않는 것을 시험으로 증명한 경우, immutable tuple snapshot 재사용 가능. Cache 객체와 Tensor의 mutation 여부를 반드시 audit한다.
3. Runtime이 유효한 독립 K/V 전달을 지원하지 않는다면 숨김 deepcopy, Full 재계산 또는 Prebuilt Request별 Cache Pool로 회피하지 말고 `UNSUPPORTED`로 기록한다.

**금지:** `Full(X)`의 K/V를 나중에 잘라서 Source Cache로 사용하는 행위, Target 측정 중 Prefix를 다시 Prefill하는 행위, Cache를 반복 간에 누적 성장시키는 행위, 타이머 밖에 Request별 Cache 사본을 무제한 미리 만드는 행위(별도 `IDEAL_DIAGNOSTIC` 제외). 모두 실제 Prefix Forward Skip 주장을 왜곡한다.

Cache 콘텐츠의 비싼 Hash/Parity/Row shape audit은 최소 계측의 요청 타이머 밖에서 시행한다. 단, 실제 서비스를 실행하는 데 필요한 사본 생성·K/V 전달·Cache 조회는 타이머에 포함한다. 비교 기준과 포함/제외 경계는 명확히 명시한다.

## 3. B1 고정 실험 케이스

| Case | 모델·Dtype | L | P | S | 목적 | 측정 |
|---|---|---:|---:|---:|---|---|
| Smoke-A | OPT-125M FP32 | 32 | 16 | 16 | 기본 Forward/Cache/Logit 정합성 | 3 warmups, 3 measured(탐색) |
| Smoke-B | OPT-125M FP32 | 32 | 31 | 1 | Suffix 길이 1에서도 Position/Cache 동작 | 소수 기능 반복 |
| Smoke-C | OPT-125M FP32 | 32 | 0 | 32 | Full과 동일한 no-prefix control | 기능 검증 |
| FP16-A | OPT-2.7B FP16 | 128 | 64 | 64 | 본 모델 캐시 동작 및 Strict 결과 | 3 warmups, 3~5 paired |
| FP16-B | OPT-2.7B FP16 | 128 | 127 | 1 | 거의 전체 Prefix 재사용 | 소수 기능 반복 |
| FP16-C(선택) | OPT-2.7B FP16 | 256 | 192 | 64 | Context 증가 Smoke | GPU memory preflight 후 2~3회 |

기본 `cache_device=cuda:0` (Source와 Target 동일 GPU). CPU→GPU KV 전송은 별도 R2-B4로 미룬다. B1은 Full/Suffix Backend `eager`를 일치시키고 Compiler/FlashAttention/Quantization/CacheGen/torch.compile 등의 혼합 최적화를 도입하지 않는다.

**제약:** L, P, S 및 max_position_embeddings를 확인, `S>=1` 유지, `P<L`. GPU 스모크를 통과하기 전 OPT-2.7B 대규모 Sweep 금지. 새로운 R2-B1 수치와 R2-A 수치를 같은 Baseline으로 합쳐 통계 처리하지 않는다.

## 4. 정합성 Gate

1. **입력/Namespace:** Prefix Token IDs가 Full/Source/Target에서 byte-exact 일치; Model resolved revision, Weight fingerprint, Adapter user/name, PEFT weights fingerprint, Tokenizer revision, dtype, attention backend, training/dropout, Device, BOS/padding/position 정책 동일. 가능한 경우 Cache Entry metadata에 전부 바인딩.
2. **KV 형식/길이:** Prefix의 모든 Decoder Layer에서 실제 `K`, `V`를 저장; expected `(batch, heads, P, head_dim)`(설치 버전마다 저장 형식 확인), dtype/device/stride/hash; H 실행 전 cached length = P, H 실행 후 유효 output KV length = L; 재측정 전 Prefix snapshot은 계속 P.
3. **물리적 Forward Skip:** Layer별 Call Count와 Hidden/Input Token axis를 Hook/Trace로 검사. F는 각 Layer `L`, H는 각 Layer `S` 토큰만 처리. H Target 내부 `PREFIX_SOURCE_PREFILL` 호출 0, Prefix QKV 계산 0, 전체 Token에 대한 별도 Hidden/FFN 계산 없음; 나머지 Suffix Attention은 전체 P+S Context를 보도록 증거 저장. CUDA kernel count는 B1 핵심 Gate 아님.
4. **수치 평가:** F repeat vs F, F의 Suffix Logits vs H, Last-Position Logits vs H; `torch.equal` Exact, strict `atol=rtol=1e-3`, 최대/평균 절대 오차, 상대 L2, tolerance violation count/ratio, Argmax agreement, optional KL. FP16 Shape 변화로 STRICT_FAIL 가능하며 **그 자체로 구현 실패를 확정하지 말 것**. 단, 모델/Prefix/Position/Mask 오류가 남아있는 실패는 `FAILED/UNVERIFIED`로 명시. `Argmax`로 STRICT_FAIL을 덮지 않는다.
5. **Namespace Negative Tests:** Prefix Token 1개라도 다르면 cache hit 거부. `user_a`에서 만든 KV를 `user_b`로 재사용 거부(두 Adapter의 파라미터가 달라진다면 필수), Model/Revision/Dtype/Backend/Device/Position/Mask 불일치 거부. Prefix가 전체 Input의 정확한 처음 P개가 아니라면 거부. 구별 가능한 rejection code 반환.
6. **Repeated-run invariance:** 동일 KV source snapshot을 여러 번 사용해도 pre/post content 동일, Target Logits 변화/누적 길이 없음, Suffix `S`개 only 계속 유지, 전체 키/값 길이 기대치 일치.

필요한 API가 지원되지 않아 어떤 Gate도 재현할 수 없다면 억지로 PASS 처리하지 않고 단계별 `UNSUPPORTED / UNVERIFIED`를 남긴다.

## 5. 최소 Latency/비용 측정 — B1에서 필요한 만큼만

- R2-B1 최소 Paired Wall ms는 동작 예비 평가로 제한. `torch.profiler` 비활성, CUDA 전후 동기화, warmups 3 + measured 3~5. 입력 L과 P별 F/H 순서를 seed 고정해 균형 조정.
- **F Native Full `use_cache=True`**, H Target `use_cache=True` (서로 같은 Cache 생성 출력 조건). Model Load, Fixture 생성, Source Prefix prefill, 긴 Hash는 Warm Target latency 밖. Target에서 Clone/Prepare가 필요하면 그 비용을 포함하고 세부 분리 값 저장.
- **별도 Source `prefix_prefill_ms`, Cache Snapshot/Clone 비용, cache_bytes, residency 기록**. `prefix_prefill_ms`는 원본 요청 별도로 계산(진짜 Source 요청으로 배분하는 경우와 Dedicated Source로 배분하는 경우)하고 완전한 시스템 지연비용이라고 착각하지 않는다.
- Primary B1 성공은 correctness/Forward audit이며 Latency는 탐색. B2는 Warm/cold 조건과 적어도 여러 독립 Run에서 평균/median/p95, Paired CI, 실제 E2E cost를 검증한다.
- `use_cache=True` 및 Output Logits 선택 의미가 R1(`use_cache=False`)과 다르므로 R1 latency를 R2-B1 Full 비교 기준으로 재사용하지 않는다.

**단위/부호:** `D(F,H) = Full_ms − ExactPrefixWarm_ms` (양수면 H가 빠름), `speedup=Full_ms/H_ms`. Source 비용을 제외한 **conditional Warm Target**으로 표시해야 하며, 정확성 요건 미달 시 `correctness_qualified_speedup=false`.

| Target은 **Suffix S개만** 모든 Decoder Layer를 처리 | 필수 PASS |
| Prefix Cache P 유지/Target 결과 Cache L로 증가, 반복 안정 | 필수 PASS |
| FP32 Smoke: Correctness/Parity/Cache Integrity 검증 | 필수 PASS (Numeric exact 여부 별도 표기) |
| OPT-2.7B FP16: Strict PASS/FAIL 원인·마지막 Argmax 등 정량 기록 | **측정 완료** (Strict FAIL이어도 설명 가능, B2 성능 주장 별도 제한) |
| 최소 Paired Warm Latency, Source/Cache 비용과 타이머 경계 | 측정 또는 제한 사유 명시 |
| 실물 GPU 결과 없는 로컬 Codex 단계 | `IMPLEMENTED_LOCAL_ONLY`로 명시; 완료 주장 금지 |

**최종 해석:** R2-B1이 성공해도 SemCache의 임의 Semantic Subsequence 재사용이나 Cross-user Adapter KV 공유를 정당화하지 않는다. R2-B2 성능/품질 및 R2-C 원 논문 Baseline과 분리한다.
