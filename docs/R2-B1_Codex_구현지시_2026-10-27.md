# Codex 구현 지시서 — R2-B1 Exact Prefix KV Cache Baseline

## 0. 역할과 목표

Repository: `/data/khuss/repos/GP_semcache` (사용자의 작업 로컬 환경). 최근 확인 branch `exp/raw-semcache-r2`, HEAD `df9aecce...` — 실행 시 반드시 실제 Git HEAD 재확인.

**R2-B1만 구현하라.** 목적은 `facebook/opt-125m` 및 `facebook/opt-2.7b`에서 사용자/모델/토큰/위치가 정확히 동일한 **Prefix K/V Cache**를 재사용하고, Target의 **Suffix만** Forward하여 실제 Prefix Layer Forward 생략을 검증하는 것이다.

참고 문서: `R2-B1_실험명세_2026-10-27.md` (우선 읽고 충돌 시 이를 기준으로, 구현상 미지원 부분을 문서화).

**이것은 기존 SemCache QKV Projection-only 구현을 고치는 일이 아니다.** 독립 실행 경로를 추가한다. 이 단계에서 품질을 희생하거나 외부 Semantic Matching으로 캐시를 재사용하지 않는다.

## 2. Forward 인터페이스와 Prefix KV Cache 계약을 탐지·명문화하라

실제 설치된 Transformers/PEFT의 `OPTForCausalLM.forward`와 PEFT wrapper에서 다음을 검사하라.

- `use_cache=True`, `past_key_values`, `attention_mask`, `return_dict` 지원 여부
- `Cache` 클래스 vs legacy tuple K/V; layer별 K/V Shape, Sequence Axis, Dtype, Device, Stride
- `position_ids`, `cache_position`, `logits_to_keep`/`num_logits_to_keep` 등 optional 인자 지원 여부. Unknown argument 전달 금지.
- OPT Learned Positional Embedding과 Prefix Length 기반 Suffix 위치; OPT에 RoPE라고 가정하지 마라.
- 최소 계측 때 `eager`, `output_attentions` 등 flag을 Full/Source/Target에서 일치시키고 기록하라. R1의 `use_cache=False` Full ms를 R2-B1 Full로 대체 금지.

API 지원이 모호하면 실제 Runtime Smoke에서 확인하고 `UNSUPPORTED_API` 또는 `UNVERIFIED_POSITION`으로 보존하라. 새로운 모델 로딩 API나 Transformers 강제 Upgrade는 하지 마라.

## 3. 독립 실행의 세 경로

F `FULL_USE_CACHE`: 정확히 같은 전체 token IDs `X`(L)를 한번 Forward하며, `use_cache=True`; 출력 Full logits all positions(필요한 값)와 native KV를 받는다.

S `PREFIX_SOURCE_PREFILL`: `X[:P]`만 **독립적인 실제 Forward**로 K/V 생성. Source만의 `prefix_prefill_ms`, K/V 메모리 및 Prefix Metadata를 보존. 절대로 Full(X) 결과를 잘라 Source KV로 사용하지 마라.

H `EXACT_PREFIX_WARM`: Source K/V를 `past_key_values`로 전달하고 입력은 `X[P:]`인 Suffix만 전달하여 Forward한다. Attention Mask 길이는 P+S, 각 Decoder Layer 신규 Query 길이는 S, KV 사용 범위 P+S. Source Prefix를 Target 안에서 재연산하지 마라.

`P=0` 은 no-prefix control이므로 F로 명시적으로 퇴화하고 캐시 HIT으로 집계하지 않는다. `P=L`/`S=0`은 기본 실험에서 거절.

For all: batch 1, padding 없음, model.eval(), inference_mode(), `user_a` adapter 고정(기본), dtype/device/backend/model revision 동일. Token IDs 직접 전달; BOS, Position, Tokenizer Roundtrip의 일관성 강제.

## 4. 가장 중요한 요구: Cache Mutation 방지

Modern `Cache`는 Target의 Suffix 처리 과정에서 Prefix Cache를 **in-place mutate**할 수 있다. 이를 방지/검증하라.

- Source가 가진 canonical Prefix K/V는 매 Target 전후 Shape/Value/Hash가 같아야 한다.
- 각 H 요청에서 Prefix Length=P에서 새로 출발해야 한다; H output KV의 Length=L, Target 이후 canonical Source Length는 여전히 P.
- Legacy tuple 전달이 실제 버전에서 재사용 가능한 불변식인지 검증할 것. 그렇지 않으면 정상적인 독립 Cache Container/clone을 만들되, **반복마다 필요한 clone/copy/allocate 비용은 Warm Request timer 내부에 포함**할 것.
- 비용을 숨긴 Prebuilt KV Pool이나 Source 재전방 처리, 실제 Cache 길이 Reset 없이 반복 실행 금지.
- Prevalidated immutable source와 Target materialization 단계를 분리하고, 타이머 경계를 manifest로 저장하라.
- Canonical snapshot의 Hash/Layer parity는 최소 측정 바깥에서 수행하고, 실제 요청에 필요한 prepare/memcopy는 내부에서 수행한다.

## 5. Cache Namespace/Exact-Prefix 안전성

Fingerprint에 최소 다음을 포함하라:

- model ID, resolved revision, base weight identity
- tokenizer ID/revision 및 tokenization/BOS strategy
- PEFT synthetic adapter ID, rank/alpha, **실제 LoRA weight hash**, active adapter
- dtype, backend, device/cache-device, eval/dropout
- 정확한 Prefix Token IDs, Prefix Length, position/mask convention

`cache_hit`은 위 모든 조건이 일치하는 경우만 가능하다. `user_a` Source를 `user_b` Target에 적용하면 명시적 `REJECT_ADAPTER_MISMATCH`. Prefix 1 Token 변경, Prefix가 중간 구간, 다른 Model/Revision/Position/Mask/Dtype 모두 명시적으로 거절. **실제로 다른 조건을 시도한 경우만 테스트 통과로 기록**, synthetic metadata stub 테스트는 별도 표기.

Semantic encoder/cluster/w3, CacheGen, cross-user 공유는 이 기준선에서 실행하지 않는다. `semantic_reuse_safety_claimed=false`.

## 6. 물리적 Forward Skip 및 정확성 감사

별도 Untimed/Instrumented Pass에서:

- 모든 Decoder Layer `forward`와 필요한 Projection/FFN 모듈 Pre-Hook으로 실 처리 Token 입력축 측정.
- Full에서 Layer별 Query Length=L; Target에서 각 Layer Query Length=S. Target 중 추가 Prefix Forward 호출은 0.
- Prefix Source에서 Cache K/V Length=P, H 결과 Cache KV Length=L, Cache Cross-Layer Counts 맞는지 검증.
- Target Suffix Attention이 P+S개의 KV를 사용하고, causal masking / absolute position이 맞는지 실제 모델 API 및 hook에서 확인.
- Source Hash/Cache metadata/adapter & model weight 불변 및 반복 3회 이상 동일 target output 확인.

Numeric:

- Full Logits 전체 길이 L의 **`[:, P:, :]`** ↔ H Logits S의 **`[:, :, :]`**, Last-position Full↔H를 비교하라.
- Prefix Source 마지막 Logit↔Full at `P−1` 은 별도의 Prefix 동일성 sanity로 검증하라.
- `torch.equal`, strict `torch.allclose(atol=rtol=1e−3)` + violation count, max/mean abs error, relative L2, last-token Argmax, Top-K(옵션).
- FP16에서 GEMM Shape 차이로 STRICT_FAIL이 날 수 있으므로 결과를 수정하거나 tolerance를 완화하지 않는다. 위치/캐시 로직 오류와 numerical difference 가설을 구분하여 보고한다.
- Full Last Logit과 H Last Logit은 `X` 전체를 처리한 다음 토큰 예측이다. Prefix 경계 예측 `P−1` Logit과 혼동 금지.
